# Facilitator guide

This guide describes intended preparation and evidence paths. It is not hidden from learners and
does not contain copy-paste final patches.

## 1. Unexpected document guidance

- Start the frontend with `DOCUMENT_GUIDANCE_V2=true` and the API normally.
- Useful evidence: startup environment, `configuration.ts`, identity-document route and domain
  mapping.
- Ask why editing the template alone does not alter derived guidance.
- Reset by stopping the frontend, removing the variable and restarting it.

## 2. Frontend-to-API boundary

- Stop the API or start the frontend with `ADDRESS_API_BASE_URL` pointing to an unused local port.
- Useful evidence: API health URL, safe browser error and the frontend request log. With no API
  process, absence of a matching Java log is itself evidence.
- Ask which process owns the failed outbound request and why browser details remain safe.
- Reset the base URL, start the API and restart the frontend.

## 3. Controlled API failure

- No code preparation is required. Use `ZZ9 9ZZ`.
- Useful evidence: matching request IDs, frontend response status, Java request log and Problem
  Details generated by the existing exception handler.
- Ask learners to distinguish deterministic training failure from random instability.

## 4. Focused failing test

- On an exercise branch, change one visible text expectation in a focused route test without
  changing application code. Show learners the test-file path, not the changed line.
- Useful evidence: assertion expected/received output and manually observed browser behaviour.
- Reset only that prepared file after checking `git status` and `git diff`.

## 5. CI/environment difference

- Prepare one harmless formatting difference, or use a managed environment with the wrong Node
  major version. Do not introduce a timing failure.
- Useful evidence: the first failed CI step, `npm run format:check`, `.node-version`, `package.json`
  and `npm run doctor`.
- Reset the prepared file or select Node 22, then rerun the exact failed command.

## Managing fuller solutions

Anything committed here is discoverable. Keep assessed final patches outside the learner handout,
or use branches/tags whose access and timing the facilitator actually controls. Prefer discussion
prompts and evidence paths here so learners still have to form and test their own explanation.
